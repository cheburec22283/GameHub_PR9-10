# GameHub — практические работы 5–10

Учебная платформа продажи компьютерных игр. Восемь профилей FastAPI собираются в отдельные образы из общего Dockerfile. У каждого сервиса своя PostgreSQL, события передаются через RabbitMQ. Проект восстановлен по контрактам и примерам из отчёта ПР5–8. Тесты и реализация хранилища написаны для восстановленной версии.

## Локальный запуск

Из каталога, в котором находится `compose.yaml`, выполните:

```powershell
docker compose up --build --wait --wait-timeout 180
python tools/e2e_check.py
```

Скрипт проверяет покупку и отмену заказа, ответы об ошибках, наличие HTTP-метрик восьми сервисов и наличие общей трассы для оплаты, заказа, лицензий и библиотеки.

| Компонент | Адрес |
| --- | --- |
| Swagger UI сервисов | http://localhost:8001/docs – http://localhost:8008/docs |
| Prometheus | http://localhost:9090/targets |
| Grafana | http://localhost:3000/d/gamehub-red |
| Jaeger | http://localhost:16686 |
| RabbitMQ | http://localhost:15672 |

Порядок сервисов по портам 8001–8008: license, order, user, publisher, catalog, payment, library, review. Для первого входа в локальную Grafana используются стандартные `admin/admin`.

Остановить стенд с сохранением данных:

```powershell
docker compose down
```

Модульные тесты, без Docker и сторонних Python-библиотек:

```powershell
python -m unittest discover -s tests -p test_domain.py -v
```

## ПР9 — настройка GitHub Actions

`.github/workflows/gamehub.yml` запускает матрицу на восьми сервисах при push, pull request и ручном запуске. Каждая задача запускает модульные и интеграционные тесты с PostgreSQL и собирает свой образ. После матрицы запускается Compose со сквозной проверкой. Шаги доставки запускаются после успешного CI в основной ветке.

### Docker Hub

Для `review-service` укажите имя аккаунта в GitHub Actions variable `DOCKERHUB_USERNAME` и токен с правом записи в secret `DOCKERHUB_TOKEN`. Создайте или выберите репозиторий `gamehub-review` и включите доставку переменной `ENABLE_DOCKER_HUB=true`. Тег образа равен SHA коммита.

[Опубликованный образ `cheba228/gamehub-review`](https://hub.docker.com/repository/docker/cheba228/gamehub-review/tags) доступен пользователям с доступом к этому репозиторию Docker Hub.

### Настройки для развёртывания в Yandex Cloud

Облачные ресурсы подготовлены: приватная ВМ с PostgreSQL и RabbitMQ, отдельная группа безопасности и строки подключения в Yandex Lockbox. Workflow использует GitHub Workload Identity Federation и получает краткоживущий IAM-токен без `YC_KEYS`. В `.github/gamehub-cloud.json` хранятся только несекретные идентификаторы.

Конфигурация `enabled: true`; облачная задача запускается только после прохождения проверок и события в основной ветке. До успешного результата этой задачи нельзя считать контейнер развёрнутым. Точный статус, ID образа и ревизии записываются в GitHub Actions summary.

`user-service` развёртывается как приватный Serverless Container в VPC. После deploy конвейер проверяет отказ без токена, авторизованный `/health`, регистрацию и чтение пользователя, HTTP-метрики. ID контейнера, ревизии и образа записываются в GitHub summary. Доставка события RabbitMQ требует отдельной проверки.

Полный порядок настройки федерации, Lockbox, ролей и smoke-проверки описан в [руководстве облачного развёртывания](docs/cloud-deploy.md). Облачный job не требует входа в GitHub через браузер и записи новых GitHub Secrets. Существующая конфигурация Docker Hub сохраняется.

## Проверка для отчёта

1. GitHub Actions: результат восьми задач матрицы и задачи E2E.
2. Docker Hub: тег SHA образа `gamehub-review`.
3. `user-service`: успешный запуск в Docker Compose и регистрация пользователей в сквозном сценарии.
4. Prometheus: восемь целей `UP`. Grafana: панель `GameHub — HTTP RED` после запуска сценария.
5. Jaeger: ссылка на трассу в выводе `tools/e2e_check.py`. У трассы оплаты видны HTTP-запрос, публикации и обработки событий в четырёх сервисах.
